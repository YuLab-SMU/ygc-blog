图片会躲，图会动，还能点着看：ggimage 这一年

图片会躲，图会动，还能点着看：ggimage 这一年

Oct 15, 202619 min read

[!一句话版本：ggimage 这一年的更新里，挑几个真正影响画图的讲：图片自己躲开重叠、图片可以只给宽或只给高、图例里放真图、把图片钉在数据坐标上、用帧数据把图做成动画、GIF 拆成帧当原料、鼠标放上去就出数据，外加几个修掉的坑，比如 NA 原来会画出纳米比亚的国旗。]

有人在 GitHub 上提了个 issue，说用 geom_image() 画 GIF 只出第一帧，他想要完整的动画。

这个需求我当时回不了，因为 geom_image() 画的是静态图，一个 raster grob，画完就完了，它压根不知道什么叫时间。

一年过去，这个包攒了不少东西。我不打算念更新日志，只挑几个真正画出来好看的，跑给你看。

图片自己躲开

散点图上放图片，最怕的就是点挤在一起，因为图片是个方块，点一密就糊成一坨，谁也不认识谁。

geom_image_repel() 就是治这个的，它和 geom_image() 的用法完全一样，只是画之前会先算一遍哪两张图叠了，再把它们推开。

左边是 geom_image()，中间那几团已经不能看了；右边换成 geom_image_repel()，一张是一张，全部分开。

这一点要注意，被移动的只是画图的位置，数据本身没有动，坐标轴、刻度和别的图层全都照旧。

它还有四个参数可以调，max.iter 控制推多少轮，force 控制每轮消掉多少重叠，box.padding 给每张图留一圈空隙，direction 限制只沿 x 或 y 滑。

整个过程是确定性的，同样的数据、同样的参数，每次跑出来一模一样，不查网络也不碰随机数。图重画一百次，也不会今天长这样、明天长那样。

有一对功能单拎出来都是好的，凑一起是坏的，就是 geom_image_repel() 和 list 列。图片按行装在 list 列里，再交给 repel 去推，它拿到的不是那张图，是套着图的那个一元素列表，于是它认不出来，每一行都警告一句 Unexpected img type: list，然后一张也不推。画出来和直接 geom_image() 一模一样，看不出哪里出了问题。现在 repel 会先把列表拆开，每行量自己那张图的尺寸，警告没了，也真推开了。

只给宽或只给高

上面那句 width = .12，就是新加的。

以前 geom_image() 只有 size 和 by 两个参数，size 是个比例，by 告诉它这个比例按宽算还是按高算，你没法单独指定一个方向上的尺寸。现在 width 和 height 都能给，可以给一个，也可以给两个，规则是这样的：

只给 width，高度按图片自己的宽高比算出来；只给 height，反过来。三个 R 标大小不一样，但都是正的，没有哪个被压扁。

两个都给，就照你给的这个框画，框的比例和图片的比例对不上时图片会变形。这是你想要的效果时（比如把图片铺满一个格子），它才给；否则只给一个方向就够了。

width 和 height 也能按行给，上面那张图就是这么画的，三行三个尺寸。它们优先于 size，某一行的值给了 NA 或者负数，那一行退回 size 的算法，不拖累别的行。

图例里放真图

以前 geom_image() 的图例，放的永远是本包的 logo，不管你数据里是什么图，图例都是那个 R 标。

现在设一个全局开关，图例里画的就是真正的图片：

这张图还有另一半故事，d$img 那一列是一个 list 列，每行装一个 magick 图片对象。以前 image 映射只认字符列，一行一个路径或 URL，现在 list 列也认，每行画自己那张图，缓存按图片内容算，不按对象的内存地址算。

这个差别很要命，以前两张尺寸一样的图可能共用一个缓存条目，画出来张冠李戴。现在看内容，是谁就是谁。

钉在坐标上

geom_bgimage() 用图片做背景，这个功能早就有了，只是以前它只会把图片拉伸到铺满整个 panel，图片比例和 panel 不一样就变形。

现在它多了 pixel、x、y 和 scale 四个参数：指定图片的某个像素（c(列, 行)，从左上角数）钉到数据的某个点上，scale 定一个像素等于多少数据单位。

四个格子，同一张图，钉的是不同的像素：左上图钉左下角，图在红点的右上方；右上图钉底边中点，图架在红点上；左下图钉右下角，图跑到红点左上方去了；右下图钉图片中心，红点就压在 R 标正中间。

锚定只看数据坐标，不看图片多大、也不看 panel 多大，窗口一拉，图就跟着数据走。

要比例不失真，记得加 coord_fixed()，因为 scale 在两个轴上是同一个数，轴不等比的时候图会被拉扁。

让图动起来

回到开头那个 issue。

GIF 的完整动画，ggimage 还是不做，因为一个 raster grob 画一个静态图，这是 grid 的规矩，我不改它。

动画交给 gganimate，状态和帧率归它管，渲染也归它管，ggimage 只管一张一张的图。两个包互不认识，只在一张数据表上碰头。

思路是帧数据：先把动图源拆成一堆静态文件，然后一行一个（图形, 帧），transition_manual() 沿着帧号走。

三个图形，三种活法：一个在原地转圈，一个从左走到右，一个蹲着不动。

这是从动画里抽出来的四帧，横着排开，转圈那个的角度变化、走路那个的位置变化，一眼就能看出来。

静态的画法还是一行一张图，和以前完全一样，动画只是多了一列帧号、多了一句 transition_manual()。

把 GIF 拆开

上面是让 GIF 当产物。它也能当原料，而且这才是那位提 issue 的小伙伴真正想干的事：手上已经有一个动图，想让它进图。

这个现在能做了，用的就是上一节那个 list 列。先看直接把文件名喂进去的：

工时越多心情越差，趋势是对的，但十六组仓鼠摆的是同一个姿势，整整齐齐，像复印出来的。geom_image() 拿到 GIF 路径只取第一帧，不报错，也不警告，我数过，一条都没有。

image_read() 读一个 GIF，回来的不是“一张动图”，是五张静图摞在一起，length() 数得出来。as.list() 把它摊开，每个元素是一帧，还是一个 magick-image，剩下的和上一节一模一样。中间一个文件都不落，不用先拆成一堆 PNG。

全员在跳。

五帧摊开，每帧的姿势都不一样。GIF 到了 PPT 和打印稿里只会剩下第一帧，这种场合就看这条。

有个坑我自己先踩了：取第 k 帧要写 fr[k]，不能写 fr[[k]]。fr[[2]] 回来的是个 bitmap,rgba，长度两万，正好是一百乘五十个像素再乘四个通道；fr[2] 才是长度 1 的 magick-image。喂错了会警告 Unexpected img type，然后画一张空白，动画跑完满屏皆白，我还以为是帧率没调好。

渲染器还有两个规矩。magick_renderer() 的 fps 必须是 100 的因子，填 8 直接报错，而 gifski_renderer() 填 8 好好的，换个渲染器就挂。gifski 还会合并它认为重复的帧，上一节那份十六帧的源文件，进 GIF 只剩十二帧，问题出在渲染器，它觉得那几帧没必要。

素材是 Wikimedia Commons 上的 File:Hamster3.gif，CC BY 2.5，4 KB，五帧，每帧三只。白底的动图落在 theme_bw() 的 panel 上几乎无痕，实景背景的会糊一圈底色出来。

鼠标放上去就出数据

图上的点，能画出来的信息就那么多，再多就得靠颜色、靠大小、靠图例，挤到一定程度就没法看了。

geom_image_interactive() 走另一条路：图片还是画在图上，但鼠标放上去可以弹出一段文字。它靠的是 ggiraph，这个包在 ggimage 的 Imports 里，装 ggimage 就带上了。

数据用包自带的冬奥奖牌榜，十个国家，金银铜都有。

tooltip 就是要弹出来的那段文字，按行给，一行一段。data_id 是给每个图形起的名字，ggiraph 靠它区分谁是谁，opts_hover 那类效果要作用在单个图形上，就得先有这个名字。

然后出 HTML：

opts_hover 是鼠标停在上面时长什么样，opts_hover_inv 是没被停的那些长什么样，一个发光、其余淡到两成，眼睛立刻就找到你在指哪个。tooltip 里的 \n 会被换成 <br>，想分几行就写几个 \n。

浏览器里打开就是这个效果：

光标挨个移到瑞士、奥地利、荷兰、挪威、美国，每停一处，被指的那面旗亮着、描一圈橙边，其余九面淡下去，旁边弹出这个国家的金银铜和总数。这张 GIF 是浏览器里录下来的，不是拼的。

两个坑。

一个是国旗。geom_flag() 的旗子从 raw.githubusercontent.com 下载，这个域名在有的网络上不通，不通也不报错，也不警告，就是画出一片空白。所以我先把十面旗抓到本地，image 那一列给本地路径。

顺带说一句 girafe() 什么时候内嵌图片。它写进 HTML 的是图层已经画出来的东西，magick 对象、本地文件、URL 都一样，编成 base64。看着像外链，是因为那张图压根没画出来。URL 是在建图那一刻取的，取不到，存下来的 HTML 里就永远缺这张图，所以要走网络的图，最好先落一次盘。

另一个是 lib/。save_html() 生成的 HTML 会引用同目录下 lib/ 里的几个 js 和 css，那是交互逻辑本体，少了它旗子能显示但鼠标没反应。传给别人得连着这个目录一起传，或者把 lib/ 里的东西内联进去。

表情不出来了

geom_emoji() 这个功能坏了一阵子，而且坏得很安静。

它从一个 CDN 下载表情图片，旧的那个主机下架了，域名却还在，你请求它，它回你一个 200，正文是一段 35 字节的文本占位符。

35 字节的文本不是 PNG，画出来的结果就是一张空白，没有报错也没有警告，表情就是不出来。

我把主机换了，现在能画了：

拟合线穿过去，离得远的点哭，离得近的笑。image 可以按行算，一行一个表情，这就是它的用法。

纳米比亚的国旗

geom_flag() 用两个字母的国家代码画国旗，缺数据的时候，那一列是 NA。

toupper(NA_character_) 得到的是字符串 "NA"，而 "NA" 恰好是纳米比亚的国家代码，那个旗帜仓库里还真有 NA.png 这个文件。

所以你少一个国家的代码，它就给你画一面纳米比亚的国旗，理直气壮。

现在 NA 不画了，空就是空，另外几个非法的写法（空的、带空格的、us/ca、../x）也一并不画，顺便堵住了路径穿越的口子。

类似的坑还有几个，.eps 以前按 ImageMagick 默认的 72 dpi 栅格化，画出来糊，现在统一 300 dpi；geom_subview() 的首个参数写法，文档里印了多少年，代码里早就跑不通了，现在又通了。
